# 25 · 兼容与版本（一页看懂该下哪个）

> 期望效果：看完这一页，你能自己回答三个问题 —— **我的游戏能装吗**、**该下哪个 zip**、**装错了会怎样**。
> 与验收数字有关的内容在 [`docs/wiki/版本与验收.md`](wiki/版本与验收.md)；本页只管"兼容"。

## 一、一句话

**当前发布 `v4.25`（正式发布 · Latest），只支持 Minecraft Java 版 `1.21.6`。** 两个变体都要求 `pack_format = 80`；版本不对时游戏会把包判为"版本不符"（黄色提示，通常仍可强制启用，但本包**没测过**别的版本，别这么干）。


## 二、版本 × 变体矩阵

| 变体（zip） | 目标 MC | `pack_format` | 要不要实验性玩法 | `pack.mcmeta` 里有 `features` 吗 | 装不进世界会怎样 |
|---|---|---|---|---|---|
| `doom.nats-v4.25.zip`（默认） | 1.21.6 | 80 | **不用** | 没有 | 正常加载 |
| `doom.nats-v4x-experimental-v4.25.zip`（实验性） | 1.21.6 | 80 | **要**：创建世界时开「矿车改进 / minecart improvements」 | 有（`minecraft:minecart_improvements`） | **整包被拒**（不是警告，是加载失败） |

两个变体是**物理分开的两份产物**：`features` 字段是整包级的，引擎要么收、要么拒。所以"能不能装"由变体决定；"行为回不回滚"由游戏里的开关决定（见 [`18-配置手册.md`](18-配置手册.md)）。

## 三、为什么实验性变体要借一个"矿车"旗标

1.21.6 可用的实验性旗标只有三个（都来自原版自带数据包）：`minecart_improvements` / `redstone_experiments` / `trade_rebalance` —— 没有"自定义数据包"这种旗标。所以只能**借一个原生旗标当引擎门**。选「矿车改进」的理由：它只改矿车运动，对刷怪/战斗/交易影响最小。

**代价（必须知道）**：开了这个实验性玩法的世界，**同时**也会拿到原版的矿车改动（矿车运动行为变化）。介意这一点就装默认变体。

## 四、升级 / 降级 / 换变体

| 场景 | 怎么做 | 注意 |
|---|---|---|
| 同变体升级（例如 v4.25 → 下一版） | 用新的 `doom.nats/` 覆盖旧文件夹 → `/reload` | 存档与已生成的生物不受影响；规则存在存储里，也会保留 |
| 默认变体 → 实验性变体 | 删掉旧文件夹，换上实验性 zip 的 `doom.nats/` → `/reload` | 世界必须先开对应实验性玩法，否则**换上去就加载失败**；最稳的做法是新建世界时开 |
| 实验性变体 → 默认变体 | 直接换文件夹 → `/reload` | 实验性专属内容（`near` / `on_spawn` / 预设）不会生效；写过的 `doom.nats:exp` 存储留在存档里，无害 |
| 想完全卸载 | 删掉 `datapacks/doom.nats/` → `/reload` → `/function doom.nats:mode/auto` | 这一步把 `doMobSpawning` 还回原版，**不做就会一直不刷怪** |
| 两个变体同时装 | 别这么干 | 同一命名空间只能有一个生效，另一个的行为不可预期 |

## 五、我的游戏是哪个版本？`pack_format` 怎么对？

| 你可能看到的东西 | 含义 |
|---|---|
| 单人：`.minecraft/versions/` 下的版本名；启动器里选的那个 | 你实际运行的 MC 版本，必须含 `1.21.6` |
| 服务器：`server.jar` 对应的版本（启动日志第一行会写） | 同上 |
| 进世界时聊天栏出现 "incompatible"/"版本不符" 提示 | 说明 `pack.mcmeta` 的 `pack_format` 与游戏不符 |
| `pack.mcmeta` 里的 `pack_format` | 本包的默认/实验性变体都是 **80**（= 1.21.6 的数据包格式） |

> 想看别的 MC 版本？数据包依赖 1.21.6 的实体/结构/标签 id 与 `finalizeSpawn` 语义，**不是改个数字就能跨版本**的，需要重新生成 + 重新验收（那需要作者本机的开发环境，不随本仓库分发）。

## 六、下载后自检（30 秒）

```
1) 哈希对不对：   sha256sum -c doom.nats-v4.25.zip.sha256        # Windows: (Get-FileHash .\doom.nats-v4.25.zip -Algorithm SHA256).Hash
2) 结构对不对：   解压后顶层应该只有一个 doom.nats/ 文件夹，里面第一层就是 pack.mcmeta
3) 装得对不对：   /reload 后聊天栏有一句就绪提示，且 logs/latest.log 里没有 "Failed to load function"
```

三项都过 = 下载、结构、加载都没问题；哪一项不过，按 [Issues 表单](../.github/ISSUE_TEMPLATE/bug_report.yml) 报（表单会问你要这三项的结果）。
