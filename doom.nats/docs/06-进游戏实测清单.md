## ⚠ 1. 先设开关（**最容易误判的一步**）

上游**从不给** `$enable suso.nats` 赋值 ⇒ 忠实移植版**默认永不刷怪**（表现为"装了跟没装一样"，且不报错）：

```
/scoreboard players set $enable suso.nats 1
```

`optimized`（v2）已在 `setup.mcfunction` 里默认置 1，不需要手动设。
参数旋钮（`setup` 里给的缺省）：`$period`=5 tick、`$repeat`=10 次尝试、`$cap`=128 格内 70 只。

## 2. P0 · 加载期零报错

1. 进世界后执行 `/reload`
2. 看聊天栏与 `latest.log`：不应出现红字；**特别留意**
   - `general:dimension_abyss`（应由夹具补齐；若报错说明夹具被覆盖或拼错）
   - `Unknown function` / `Unknown predicate` / `Unknown tag`（1.20.2 起会让**整个函数**失效）
3. 确认 setup 跑过：`/scoreboard players get $period suso.nats` → 应回 `5`

## 3. P1 · NBT 语义抽查（本次移植改写的字段）

> 这三条是**直接从移植后的刷怪表里摘出来的**（原样贴进聊天栏即可）。
> 验的是 1.21.6 的**编解码器是否接受改写后的字段** —— 这是无头模拟器证明不了的部分。

**① `active_effects`（药水效果）** —— 出自 `spawn/ground/dark_beach.mcfunction`

```
execute if score $rng suso.nats matches 1..500 run summon zombie ~ ~ ~ {Tags:[suso.nats.count],active_effects:[{id:"minecraft:strength",amplifier:0,duration:-1,show_particles:true}]}
```

- 期望：僵尸**永久力量 I**。核对：`/execute as @e[tag=suso.nats.count,limit=1] run data get entity @s active_effects`

**② `equipment` + `drop_chances`（组件化装备与掉落率）** —— 出自 `spawn/ground/dark_beach.mcfunction`

```
execute if score $rng suso.nats matches 501..700 run summon skeleton ~ ~ ~ {Tags:[suso.nats.count],equipment:{mainhand:{id:"minecraft:bow",count:1,components:{enchantments:{"minecraft:power":1}}}},drop_chances:{mainhand:0.0f,offhand:0.085f}}
```

- 期望：骷髅**手持力量 I 的弓**；`data get entity … equipment` 里是 bow（不是空手）；`drop_chances` 保留 `mainhand:0.0f`
- 这一条是**组件化重写的重点**（`equipment.mainhand` 现在是完整物品栈）

**③ `profile` 头颅贴图 + `attributes`（属性）** —— 出自 `spawn/ground/dark_the_void.mcfunction` 第 1 行

- 操作：把该文件**第 1 行整行**（很长，含 `profile:{id:[I;…],properties:[{name:textures,value:"…"}]}`）复制到聊天栏直接执行
- 期望：
  - 僵尸**戴着那个自定义皮肤的头颅**（不是默认 Steve、也不是空头）
  - `data get entity @e[tag=suso.nats.count,limit=1] attributes` 应列出 `max_health` 等 base 值（不是空数组）

## 4. P2 · 运行观察（真的会刷怪吗）

```
/scoreboard players set $enable suso.nats 1
/gamerule doMobSpawning false        # 可选：关掉原版刷怪，观察更干净
/tick freeze                          # 压缩验证时间（可配 /tick sprint 1000）
```

- 站到有刷怪表的群系（`spawn/ground/` 下 26 张表，如 `dark_plains`、`dark_desert`…；表按群系 + 黑暗条件派发）
- 计数（128 格内被本包刷出来的实体）：
  ```
  /execute store result score $c suso.nats run execute if entity @e[tag=suso.nats.count,distance=..128]
  /scoreboard players get $c suso.nats
  ```
- 抽查一只：
  ```
  /execute as @e[tag=suso.nats.count,limit=1] run data get entity @s
  ```
- 判据：`$c` 会随 `$t % $period == 0` 的节拍上涨、且**不超过 `$cap`**；抽到的实体 `Tags` 里应有 `suso.nats.count`

## 6. 判据与后续动作

- **P1 任一条不符** ⇒ 移植的 NBT 改写有错：按 `02-移植矩阵.md` 定位字段 → 改 `tools/port.mjs` → 重跑四连
  （`node tools/port.mjs && node tools/optimize.mjs && node tools/verify.mjs ../ported/suso.nats && node tools/sim.mjs 6000`）
- **P0 报 `general:dimension_abyss`** ⇒ 夹具没生效：`node doom.nats/tools/install.mjs --variant ported` 重装
- **P0/P1 全过** ⇒ 待你定两件事：① 交付 `ported` 还是 `optimized`；② 是否启用可选项 O4/O5/O6（默认关，见 `04-优化方案.md`）

## 附：为什么 `ported` 与 `optimized` 的开关不同

- 上游 `suso.nats` 全工程**没有任何一处写 `$enable`**（`main.mcfunction` 只读不写）⇒ 原包在 RC4 里也永不运行，靠地图脚本开。
- `ported` 忠实复刻了这个行为（不写）；`optimized` 把它当 bug 修掉（setup 里 `unless matches 1.. → set 1`，记为 O3）。
