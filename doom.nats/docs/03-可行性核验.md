# 可行性核验报告（静默核验）

- **日期**：2026-09-18
- **目标**：判定 `suso.nats` 由 1.20.1 移植到 1.21.6 的**可行性等级**与**风险边界**
- **约束**：不启动游戏、不打扰用户 → 全部结论建立在**离线取证**上

---

## 一、核验方法（证据链）

| 层 | 手段 | 权威性 |
|---|---|---|
| **E1** | 从 `1.21.6-Fabric 0.16.14.jar`（= 打过 Fabric 补丁的客户端 jar）中央目录抽取 `version.json` | ⭐⭐⭐ 官方 |
| **E2** | 抽取 `assets/minecraft/blockstates/*.json` → **1.21.6 方块注册表 1107 项**（权威全集） | ⭐⭐⭐ |
| **E3** | 抽取 `data/minecraft/tags/*` 目录名 → **原版标签目录为单数** | ⭐⭐⭐ |
| **E4** | 抽取 `data/minecraft/worldgen/biome/*.json` → **1.21.6 生物群系 65 项** | ⭐⭐⭐ |
| **E5** | 解析 class 文件常量池，仅取 `CONSTANT_String`（tag 8）字面量 | ⭐⭐⭐ 精确 |
| **E6** | 解析 class 文件 `super_class` / `interfaces`，区分 **运行时编解码器** 与 **`com.mojang.datafixers.DataFix`** | ⭐⭐⭐ 判据关键 |
| **E7** | 比对 `suso.nats` 全部 102 个函数中出现的根命令与 64 种 NBT 键 | ⭐⭐⭐ |
| **E8** | 交叉比对同捆 7 个数据包，确认外部依赖 | ⭐⭐⭐ |

> **E6 是本次核验的关键判据**。初版扫描曾误判：`ActiveEffects`、`HandItems`、`Attributes`、`CustomModelData`、`tag`、`Count` 等旧名在 1.21.6 jar 里**确实存在字符串常量**，一度看似"旧写法仍可用"。
> 进一步解析父类后发现：这些类**全部继承 `com/mojang/datafixers/DataFix`**，属于**旧存档升级修复器**，只在打开旧世界时运行，**对数据包命令里的 SNBT 完全无效**。剔除后结论反转。

## 三、可行性判定

> ### 结论：**可行（高置信度）**，属"**规则化批量改写**"而非"重写"。

| 维度 | 评估 |
|---|---|
| **架构可行性** | ✅ 包内**无**已删除的实体类型、**无**已删除的方块（除 1 项）、**无**已删除的命令、**无**已删除的谓词类型。控制流（计分板 + `execute` + `function` 递归）在 1.21.6 完全可用 |
| **改动规模** | 125 文件全部需移动（A1）；**约 400+ 处** NBT 字段需重写（B1–B6）；**2 处**逻辑缺陷必须修（A2/A3） |
| **改动性质** | 高度规则化：实体 NBT 6 类、物品组件 6 类、属性名 6 类、效果 ID 5 类，**全部可由转换器自动完成**，无需人工判断 |
| **不可自动化部分** | 仅 `CustomName` JSON→SNBT（19 处）与 UUID 规范化（4 处），规则明确，可脚本化 |
| **主要不确定性** | **无法离线证实**"改写后的 NBT 在真实 1.21.6 中被正确解析"——因为 1.21.6 无服务端 jar 可用于无头加载测试（全盘检索确认不存在），且数据包函数在加载期解析、NBT 语义在运行期才生效 |

## 五、核验边界（诚实声明）

1. **未启动游戏**，未做真实加载测试。本报告结论全部来自 1.21.6 jar 的静态取证，属于"**注册表与编解码器层面**"的证实。
2. **E6 判据（fixer vs codec）是必要非充分**：证明某字段"不在运行时编解码器中"是强证据；但"仍在运行时类中"不等于"命令期接受该 SNBT 结构"，故 B 组结论保守地采用**规范写法**而非"兼容写法"。
3. `DeathLootTable` 与 `ExplosionRadius` 两项证据不足（仅 fixer 痕迹），已列入 C 组待实测，**不作为阻塞项**——即使失效也只影响 2 个刷怪条目。
4. 全盘检索确认本机**无 1.21.6 服务端 jar**，因此无法用无头服务端做 `/reload` 级验证。本机**有** 1.21.6 Fabric 客户端与官方 Java 21 运行时（`java-runtime-delta`），具备后续实测条件。

---

## 六、结论

- **移植可行，且工作量可控**：核心是"目录改名 + `pack_format` + 两个缺陷修复 + 规则化 NBT 重写"。
- **不建议手工改包**：400+ 处规则化改写应由**转换器**完成，便于回归与跟进上游。
- **风险集中在 B 组**：这是"能加载但行为全错"的静默失败，必须靠 P1 手动 summon 抽查验证，不能只看 `/reload` 是否报错。
