# 08 · v3 改造说明（`suso.nats` → `doom.nats`）

> 三项要求一次到位：**① 宏替代重复实现 ② 生物注册表机制 ③ 命名空间改为 `doom.nats`**。
> 转换器：`tools/doomify.mjs`（`optimized/suso.nats` → `v3/doom.nats`），**不手改产物**。

## 一、命名空间重命名

`suso.nats` → `doom.nats`，**全量 323 处**，转换器按文本身份逐处替换，覆盖：

| 类别 | 处数 | 例子 |
|---|---|---|
| 目录路径 | 66 | `data/suso.nats/function/...` → `data/doom.nats/...` |
| 函数 / 谓词引用 | 83 | `function suso.nats:check` → `doom.nats:check` |
| 计分板 objective | 134 | `$period suso.nats` → `$period doom.nats` |
| 实体 tag | 63 | `Tags:[suso.nats.count]` → `[doom.nats.count]` |
| storage 键 | 4 | `suso.nats:place` → `doom.nats:place` |
| 其它（注释、描述） | 39 | `pack.mcmeta` 描述 |

配套改动：

- `minecraft:load` / `minecraft:tick` 标签指向 `doom.nats:setup` / `doom.nats:main`；
- 调试包 `doom.log`（`nats.debug:*`）内部所有 objective / tag 引用同步改名（`tools/gen_harness.py`，35 处）；
- `install.mjs` 变体表新增 `v3`（包目录 `doom.nats`、命名空间 `doom.nats`），并**强制变体互斥**——混装会双份刷怪；
- 无头解释器与模拟世界改为**自动探测命名空间**（`Interp` / `World.detectNamespace`），不再硬编码 `#suso.nats:free` 之类。

## 二、生物注册表机制

### 数据长什么样

刷怪载荷（实体类型 + 完整 NBT）从 20 张群系表里搬进 `storage doom.nats:mobs`：

```
# data/doom.nats/function/mob/reg/zombie.mcfunction（分片之一）
data modify storage doom.nats:mobs zombie_2 set value {type:"zombie",nbt:{Tags:["doom.nats.count"],...}}
```

取用端是一个宏函数：

```
# data/doom.nats/function/mob/spawn.mcfunction
$summon $(type) ~ ~ ~ $(nbt)
```

群系表因此从「3 KB 内联 NBT」变成一行一条：

```
execute if score $rng doom.nats matches 1..400 run function doom.nats:mob/spawn with storage doom.nats:mobs zombie_2
```

> 关键细节：宏替换里**字符串参数不带引号**插入，所以 `type:"zombie"` 正好拼成 `summon zombie`；
> 复合参数 `nbt` 以 SNBT 形式插入，与原内联写法逐字等价。

### 三个配套机制

1. **分片**：注册表按实体类型切分、每片最多 6 个变体（`mob/reg/<entity>[_n].mcfunction`），
   单文件峰值从 21.9 KB 压到 4.1 KB —— 避免加载期把解析压力集中在一个函数上。
2. **一次装载**：`data/doom.nats/tags/function/mob_registry.json` 列出全部分片，`setup` 里
   `function #doom.nats:mob_registry` 一次装载（幂等）。
3. **签名去重**：相同 `(type, NBT)` 只存一份 —— 48 条目服务 72 处刷怪，命中 24 次复用。

### 加一只新生物要做什么

只改注册表，**不用碰任何群系表结构**：

1. 在对应分片里加一行 `data modify storage doom.nats:mobs <id> set value {type:"…",nbt:{…}}`；
2. 在目标群系表的 RNG 区间里写 `run function doom.nats:mob/spawn with storage doom.nats:mobs <id>`。

## 三、宏替代与性能

| 指标 | v2 `optimized` | v3 `doom.nats` |
|---|---|---|
| 函数文件 | 36 | 54（含 17 注册表分片 + 装载标签） |
| 函数总字节 | 34 449 | 42 541 |
| 最大单文件 | 3 892 B（一张群系表） | 4 109 B（注册表分片） |
| **summon 行内联字节** | **26 512 B（75 处巨型 NBT）** | **28 B（全部走宏）** |
| 每场景命令数（6 000 tick） | 97 139 | 97 686（+0.6%） |

**如实说明**：宏化把加载期解析从「几十个巨型命令树」摊成「一次注册 + 轻量调用」；
但运行时每次命中要多一层宏替换，命令数 +0.6%。这是**可维护性与加载期**的优化，
不是运行期加速 —— 想要纯运行期更快，就得放弃数据驱动。

## 四、验证证据（改完必跑）

```bash
node tools/port.mjs && node tools/optimize.mjs && node tools/doomify.mjs
node tools/verify.mjs ../optimized/suso.nats    # 0 blocking / 0 warning
node tools/verify.mjs ../v3/doom.nats           # 0 blocking / 0 warning（含注册表校验）
node tools/sim.mjs 6000                         # 8/8 场景 PASS
```

- `sim.mjs` 现在跑**三方对照**（ported / optimized / v3），逐事件比对尝试流与刷怪流；
- 结果：**8/8 场景 PASS**，总刷怪 **503 = 503**，类型分布逐项相同（skeleton×118 zombie×103 creeper×97 …）；
- 解释器错误 0、未实现告警 0。

静态校验同步升级（否则注册表会让 NBT 规则静默失效）：

- `verify.mjs` 新增**注册表扫描**：逐条校验 `{type, nbt}` 的实体 id、装备槽、属性、效果、遗留 1.20.1 键；
- 新增**条目引用校验**：`with storage doom.nats:mobs <id>` 引用的 id 必须存在；
- 宏行（含 `$(`）里的 summon 不再静态判定，改为计数提示。

## 六、点位可视化（物理模型）

```bash
node tools/viz.mjs --pack v3 --ticks 1200 --open
```

产物：`reports/points.json`（原始点位）+ `reports/可视化-<时间戳>.html`（自包含三维模型，无外部依赖）。

- 数据来源与 `sim.mjs` **共用同一条执行路径**（`tools/lib/simrun.mjs`）——模型里的点就是无头验证里的点；
- 图层：尝试点 / 刷怪点（按类型着色）/ 朝向锥（俯仰正负异色）/ 地面网格 / 距离环 / 投影垂线；
- 交互：拖拽旋转、滚轮缩放、Shift+拖拽平移、双击重置；另有正俯视与正侧视两个快捷视角；
- 面板给出距离与俯仰直方图、成功率、类型计数 —— 可直接核对「俯仰偏向 0°、偏航均匀、距离按 3 格步进」这些分布特征。

> 注意：世界是**合成世界**（`groundY` 之下实心、之上按 solid/free 标签判定），不是真实地图地形；
> 模型展示的是刷怪判定所用的几何关系，而非具体方块的贴图。
