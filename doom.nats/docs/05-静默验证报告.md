## 五、静默计算**真实抓到的 3 个 bug**

这是本次验证最有价值的部分——**全部是"能加载、不报错、但行为错"的静默失败**，静态校验完全查不出来：

| # | 位置 | 现象 | 根因 | 处置 |
|---|---|---|---|---|
| **S1** | v2 `do.mcfunction` | 距离分布与 ported 不符（首个差异在第 3 次尝试） | Java `%` **保留符号**，`$rng % 32` 可为负；原二分树用 `matches ..N` 分支，**负数会一路落到最小叶(27)**，而算术式 `27+3·s` 给出负数距离 | 加 `scoreboard players operation $dist > #0` 取 max，复现原树钳位 |
| **S2** | v2 全部 roster | `region/lush_caves/light` 场景 v2 **刷怪 0 / ported 刷怪 70** | 18 张刷怪表内含 **23 处 `execute at @s[x=..,dx=..]` 区域检测**——依赖实体才有 `@s`；v2 无实体 → 命令失败 → 整表失效 | 新增 `rules/positional.mjs`，把 23 处区域检测转成 **8 个位置谓词**（含把 `predicate=general:dimension_abyss` **与** box 合并为单个 `location_check`，以保住 `unless` 的德摩根语义） |
| **S3** | 解释器自身 | `suso.nats:box/...` 报 unknown predicate | 谓词生成在**子目录** `predicate/box/`，解释器只读顶层 | 递归加载谓词目录 |

> S2 尤其典型：若不跑无头计算，只做静态校验，v2 会**通过全部检查**，但整张地图的亮侧刷怪与 4 张暗侧刷怪表会**静默失效**。

## 七、诚实边界

1. **本报告证明的是控制流等价性**：位置、朝向、距离、生物群系派发、刷怪选择、终止性、指令预算——逐事件一致。
2. **不能证明**真实 1.21.6 的 NBT 编解码器接受改写后的字段。解释器只做语法与结构校验，不做 NBT 语义校验。该部分只能进游戏实测（P1 项，见 `03-可行性核验.md` §4）。
3. 世界是**合成平原**（单生物群系、单光照层），不是 RC4 真实地形；因此本报告验证的是**逻辑**而非**关卡手感**。
4. 解释器是自研实现，其"忠实"程度受限于已覆盖的指令面（§3）；遇到未实现指令会**计入告警**而非静默忽略——本次 8 场景告警为 0。
5. `region/lush_caves/light` 场景中 ported 与 optimized 的 12 000 次尝试**完全一致**，包括区域边界处；位置均为 `~.5` 块心，故"盒判定开闭区间"的差异不会触发。

## 八、结论

> **移植可行性与优化等价性均已在无头环境中证实。**
> 忠实移植版（126 文件）与 v2 优化版（69 文件）在 8 个场景、21 100 次尝试、503 次刷怪上**逐位相同**；
> v2 同时**消灭了全部 72–83 个假实体/场景**、把 63 文件二分树压成 1 个宏、指令数下降 **8.7%**、递归深度 33 → 27、外部依赖归零。
>
> **下一步只剩进游戏实测 NBT 语义**（P0 加载 / P1 手动 summon 抽查），可用 `/tick freeze` + `/tick sprint 1000` 把验证时间压缩约 50 倍。
