> 原则：**极端场景是"把机制逼到边界"的手段**，每条都要能回答"原版会怎样、本包会怎样、差在哪"。

## 场景阶梯（E = Extreme）

### E1 单群系维度（先做）
把 overworld 的 `biome_source` 覆盖成**唯一群系**（每轮一个）：`ocean` / `deep_ocean` / `desert` / `mushroom_fields` / `dripstone_caves` / `lush_caves` / `the_void`。
断言：
1. `biome/detect` 65 张表只命中对应一张（未收录群系应保持 0 = 不刷怪）。
2. 物种分布 = 该群系 roster 权重（用 `verify_species_mix` 的生产口径）。
3. 单类别群系（`the_void`、`the_end` 族）必须显式置 `$catid=0`（v4.18/Q7 的坑）。
4. 海平面/维度参数（`check/sealevel`）在覆盖后仍指向正确维度。

### E2 限制性维度
- `has_skylight=false`（末地式）：`can_see_sky` 恒 false ⇒ 尸壳/流浪者/蝙蝠/守卫者/巡逻队的门要正确"全拒/全过"。
- `doDaylightCycle=false` + 固定 midnight/noon：光照门 (`isDarkEnoughToSpawn`) 的两端。
- `min_y` 极低 / 天花板很低：取点回退区间 `[floorY, 玩家层+2]` 的边界与退化保护。
- 世界边界（worldborder）紧贴：`isWithinBounds` 语义。

### E3 群系边界棋盘（`fillbiome`）
在一块 32×32 平台上铺 4×4 的群系棋盘（含 `river`↔`ocean`、`swamp`↔`mangrove_swamp`、`deep_dark`↔`dripstone_caves`），机器人走格子逐点采样：
- `detect_at`（候选点群系）与 `detect`（快照）在边界上的分歧率；
- 结构谓词（piece 级）与群系的交叉；
- 权重表在边界上的切换是否"整次尝试一致"（原版：物种每组只抽一次，用首个合格点的群系）。

### E4 容量 / 密度极端
- `cap.*` 拉到 0 / 1 / 1000；`batch` 1→40 阶梯；`density` 打开让 AIMD 收敛 ⇒ 观测 MSPT、归因直方图（r0..r10）、`$spawned.total` 速率曲线。
- 玩家数阶梯：0 / 1 / 4 / 10 机器人（10 需用 25566 实例，主测服 max-players=4）。
- 断言：容量门（全局 + 本地 OR 语义）在任何 cap 下都不越界；冻结快照不会造成"容量超额"（历史上的 creature 溢出就是冻结快照没恢复导致的）。

### E5 落位 / 方块极端
- AABB 边界族：半砖、楼梯、栅栏、玻璃板、雪层、地毯、含水方块、`bubble_column`、`kelp`/`seagrass`（原版 IN_WATER 只看流体）。
- 流体边界：水/岩浆交界、"水帘洞"、`#spawnable_at` 里的 snow/lava 白名单历史坑。
- 伤害方块 / 阻止生成方块（`PREVENT_MOB_SPAWNING_INSIDE`）。

### E6 红石机械（等用户提供）
- 先问清机械"制造什么条件"：挤压/推动方块改落位面、连续击杀（消失层压力）、水流冲刷、光照切换、传送门（下界传送门刷猪灵 = 不可表达项）、活塞推方块进候选点。
- 搬进测试世界后按 `_work/_prodpoint_probe.mjs` 口径做前后对比。

### E7 多机器人 × 多维度并行
10 机器人在 overworld / nether / end 三线并行：验证 per-dim 容量、per-player 本地容量、消失层隔离（`verify_multibot` 的 ②③ 就是这条的简化版）。

## 执行纪律（写死）

1. 每个极端场景都要**先冻结 `$snap_period`** 再戳分数（只冻 `$eff.period` 会被 circ/apply 一秒内还原）。
2. 探针**不预掷 `$rng`**，一律走生产分发。
3. 长任务/机器人用 `Invoke-CimMethod Win32_Process Create`（`_work/run_bg.ps1` / `_work/start_bot.ps1`）。
4. 内存预算：当前只剩 ~1.1 GB 可用 ⇒ 新世界 view-distance 6–8、heap 1.5 GB；要 10 机器人得先腾内存或停主测服。
5. 结论一律"原版会怎样 / 本包会怎样 / 差在哪 / 数字"四件套，写进 `reports/`。
