## 二、机制（改了什么，凭什么等价）

| 能力 | 生成物里的样子 | 与原版的关系 |
|---|---|---|
| `belowAny`（用例①） | `execute if score $sel.rule matches 33 if block ~ ~-1 ~ #minecraft:leaves run scoreboard players set $chk.belowok 1`，全局站立行加 `unless score $chk.belowok matches 1` | 原版 `ON_GROUND` 要求下方 `isFaceSturdy(UP)`；这里只是把白名单**扩大**到作者点名的标签 |
| `entries.json`（用例②） | `execute if predicate doom.nats:weather/thunder if score $py matches ..62 run scoreboard players add #wsum 120` + 命中区间 `#off..#hi`（`#off` 仅在条件成立时前进） | 与"**先按条件过滤候选表、再按权重掷**"逐点等价（`WeightedRandom.getRandom` 的区间语义） |

## 三、踩坑（都是真机换来的）

1. **宏行（`$` 开头）里必须有 `$(name)` 占位符**，否则**整函数加载失败**（`No variables in macro`）。
   我第一版的容量行 `$execute if score … >= $cap.now …` 没有占位符 ⇒ `check/cap`、`check/local_one` 双双挂掉
   （`/reload` 2 个 Failed to load）。修法：临时分数也带上占位符（`$cap.now_$(cat)`）。
   **教训：变体产物也必须过 `lint_ctm` 与加载期门**，不能只看默认产物的绿灯。
2. **`data get storage` 的 SNBT 是 `key: value`（冒号后有空格）** ⇒ 正则必须容错，否则读数一律 NaN（第一版探针全红）。
3. **`weather thunder` 是渐变的**：`rainLevel/thunderLevel` 每拍 ±0.01 ⇒ 雷暴要 **≈6.5 秒**才满足
   `thundering` 谓词（`>0.9`）。探针等 150ms 时读到"没雷暴"，白红了一轮。
4. **试验场必须建在已加载区块**：`if block` 在未加载区块恒假 ⇒ 判定全红（第一条试验场建在 x≈1200 的未加载区）。
5. `fill` 的"Successfully filled"是真的；`data get block` 对非方块实体目标只回 "not a block entity"，别拿它当判据。
