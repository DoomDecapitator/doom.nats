# 验收报告 · 实验性 AJ/BDEngine rig 桥接（v4.25 · 2026-09-29）

> 目标（SPEC）：把 Animated Java / BDEngine 导出的**自定义生物外观**接进刷怪层，做法是
> **「真实体当内核 + rig 当外观」**（A 方案）；**全部归实验性**，默认产物一字不动。
>
> 契约：`rules/rigs.json` 为空/缺文件 ⇒ 生成器**不产出任何 `exp/aj/**` 文件**、`spawn/emit` 也不多一个字
> （默认变体 `check_static` 仍是 **0 error / 2 warning**，与加这一层之前完全相同）。
>
> 全流程只碰**自己的隔离实例 mcserver-aj（25572 / RCON 25582）**，未触碰主服 25565，也未占用 fid（25571/25581）。

## 一、结论一行

**A 方案成立**：`ride` 能把 display 骨架挂到真实生物上（**方向必须是"rig 骑内核"**），
内核照常移动/消失，外观逐格跟随（10 步位移误差 **0.0000 格**）；内核消失后 rig 由 40t 清扫层清空（**0 残留**）；
容量按内核计入（**Δ1**，50 个 display 一个都不计）；空 `rigs.json` 时**一行代码都不生成**。
真机 **13 PASS / 0 FAIL**（rig 相）+ **2 PASS / 0 FAIL**（空 rigs A/B）。

## 三、链路（生成物里长什么样）

```
spawn/emit（@s = 玩家，位置 = 候选点）
 └─ if data storage doom.nats:sel {rig:"<id>",type:"<载体>"}        ← 非宏守卫，且**带类型**（防 $sel 残留）
     └─ exp/aj/emit_sel  [MACRO]  $function exp/aj/emit/$(rig) with storage doom.nats:sel
         └─ exp/aj/emit/<id>      execute summon <carrier> run function exp/aj/post/<id> with storage doom.nats:sel
             └─ exp/aj/post/<id>  [MACRO]（@s = 刚生成的内核）
                 ① $function doom.nats:post/$(slug) with storage doom.nats:sel   ← 标准收尾（标签/NBT/持久化/朝向/on_spawn）
                 ② data merge entity @s <carrier_nbt>（可选；隐形/静音/无 AI）
                 ③ tag @e[type=#doom.nats:exp_aj_display] add …exp.aj.pre          ← 召唤前先标记"已有的 display"
                 ④ function exp/aj/rigsummon/<id>                                  ← 外部包函数（缺包只挂本文件）
                 ⑤ 认领：没有 pre 标记的 display 全部算本次 rig（+ 根打 exp.aj.root）
                 ⑥ 挂载：把"自己不是别人乘客"的那批 ride 到内核上（载具用临时 anchor 标签精确定位）
                 ⑦ function exp/aj/on_spawn/<id>（可选钩子，例如启动第三方动画）
core/tick（实验性变体且 rigs 非空时多 1 行）→ exp/aj/tick（40t 分频）→ exp/aj/sweep
 └─ 从**活内核**做乘客闭包 → 没被波及的 rig/骨骼 = 孤儿 ⇒ kill（display 无战利品表，kill ≡ discard）
```

### 挂载方向的实测（SPEC 问的那条）

| 变体 | 命令 | 结果 |
|---|---|---|
| **rig 骑内核（采用）** | `ride <rig,limit=1> mount <内核,limit=1>` | ✅ 跟随后（tp/自走/逐格）误差 **0.0000 格**；内核保留 AI/消失层语义 |
| 内核骑 rig（反向） | `ride <内核> mount <rig>` | ❌ 不采用：内核变成乘客后**不再自己走**（被钉在不会移动的 display 上） |
| marker 当挂载枢纽 | `ride <display> mount @e[type=marker]` | ❌ 不可行：`marker` **不能载客**（"Item Display couldn't start riding Marker"） |
| 多乘客是否"序号堆叠" | 3 个 display 挂同一只 squid | 三个乘客的 `Pos` **完全相同**（同一点）⇒ 模型相对布局由各自 `transformation` 决定，不受乘客序号影响 |
| 判定"是否被骑乘" | `data get entity <display> RootVehicle` | ❌ display 上**没有**这个字段（哪怕正在被骑）⇒ 清扫改用"活内核的乘客闭包" |

**更优的挂载方式（结论）**：不要额外的中间实体，直接"**整云认领 + 只挂顶层 + 骨骼/子块靠父子关系跟随**"：
BDEngine 的组实体自带乘客方块、AJ 的骨骼是根的乘客 —— 两者都靠 `on passengers` 自动跟随，
比"每个 display 都挂到内核上"少 N-1 次挂载、也不会破坏第三方自己的层级。

**接进来的两个真实障碍**（都记下来，别再踩）：

1. **`pack.mcmeta` 用的是新 schema**：`{"pack":{"min_format":48,"max_format":200}}` —— 1.21.6 日志直接报
   `Couldn't load pack metadata: No key pack_format in MapLike[...]`，包**连"可用列表"都进不去**。
   修法（只动验收实例里的副本，不改第三方内容）：补 `"pack_format": 80` 再 `/datapack enable`。
2. **骨架不是"一棵树"**：BDEngine 导出的是 **1 个根 + 1 个空节点 + 16 个组实体（各自带 2 个乘客方块）**，
   组实体之间没有父子关系 ⇒ 只挂"根"会丢 33 块。桥接因此改成"**按 pre/差集整云认领，只挂顶层**"。

## 八、诚实清单（未做 / 做不到）

1. **主路截图未出**：mineflayer 4.39.0 在 1.21.6 上被服务端踢（`Invalid move player packet`）⇒ 无头 Edge 无画面。
   替代：副路自绘（已交付，数据来自游戏内真值）。想补真渲染的话需要先解决 mineflayer 的 1.21.6 兼容。
2. **未在真实 Animated Java 导出上跑**：本轮验收用的是第三方 **BDEngine** 导出（`calamar:summon`，50 个 display 的并列结构）。
   仓库里另有一份真 AJ 导出（`build/out/aj/golem_datapack`，`item_display` 根 + 11 个骨骼乘客），
   结构已被桥接的"骨不单独挂载"逻辑覆盖，但**没有接线验收**（时间/实例排期），因此报告里只写"设计上覆盖"。
3. **运行时刻条目（storage `doom.nats:author` / `doom.nats:exp` 的 entries）拿不到 rig**：
   那些条目走 `author/emit_rt`，不进 `spawn/emit` 的 rig 分支。要给它们挂 rig，目前只能写进构建期 `rules/entries.json`。
4. **动画驱动的规模限制来自第三方包**：`calamar:animate/**` 的 `limit=1` 让"多只 rig 只有一只在动"（原包按单体 boss 写的）。
   桥接只负责挂载，不替它改成 per-rig 调度。
5. **`count_with_carrier:false` 用的是"内核打 `PersistenceRequired:1b`"**（原版 SpawnState 会跳过持久生物）
   ⇒ 代价是它同时免疫消失层与 `debug/clear`（原版持久生物语义）。本轮只验了 `true` 分支。
6. **`claim` 是"pre 差集"而不是"半径"**：理论上如果别的系统恰好在同一次调用里造 display 会被误领
   （本包自己的链路里不可能发生）。已把半径法的问题（同点连生两只串味）留在注释里。
7. **旁证发现（未改默认产物）**：默认变体 `check/caps` 只给 `monster`/`creature`/`ambient` 写了**主世界**计数，
   `water_creature` / `water_ambient` / `underground_water_creature` / `axolotls` 只有 `.nether`/`.end` 两份
   ⇒ 主世界这 4 类的全局容量判定**恒读 0**（`check/cap.mcfunction` 读 `$cnt.$(cat)`）。这属于既有层的问题，本轮没动。
