# 诊断 · 多玩家下的消失层（P0） —— 2026-09-29

> 本轮的 P0 结论：**消失判定把"最近玩家"写成了"任一玩家"**，于是多玩家（相距 >256 格）时，
> 一名玩家身边的生成物会被另一名玩家的距离判掉。这条 bug 从 v4.17 的"逐玩家修复"里带进来，
> 一直由 `verify_multibot` ②③ 报红，此前被当成"测试侧不稳"挂着 —— 本轮定位并修掉。

---

## 1. 原版会怎样

`Mob.checkDespawn()`（1.21.6，`net.minecraft.world.entity.Mob`）：

```java
if (!this.isPersistenceRequired() && !this.requiresCustomPersistence()) {
    Player player = this.level().getNearestPlayer(this, -1.0);   // ← 参考点 = **最近的**玩家
    if (player != null) {
        double d = player.distanceToSqr(this);
        int i = this.getType().getCategory().getDespawnDistance();   // MONSTER/CREATURE/…=128，WATER_AMBIENT=64
        if (d > (double)(i * i) && this.removeWhenFarAway(d)) this.discard();
        ...
    }
}
```

要点三条：

1. 判定基准是**最近的玩家**（不是"某个玩家"，也不是函数执行位置）。
2. `despawnDistance` 按类别：**WATER_AMBIENT = 64**，其余 **128**。
3. 超距走 `discard()`（静默移除：无掉落、无死亡动画、无经验）。

## 2. 本包会怎样

### 2.1 修复前的两代写法

| 版本 | 写法 | 等价语义 |
|---|---|---|
| ≤ v4.16 | `execute as @e[tag=…,distance=129..] run void_kill`（执行位置 = 世界出生点） | "离世界出生点 >128 就消失" ⇒ 玩家离出生点稍远，**全场**生成物一拍清空 |
| v4.17–v4.21 | `execute as @a at @s as @e[tag=…,distance=129..] run void_kill` | "**存在某个**玩家离它 >128 就消失" ⇒ 多人相距较远时，**身边**的怪也被清 |

v4.17 的注释写对了意图（"生物只要在**任一**玩家 128 格内就跳过，对**所有**玩家都超距才移除"），
但 `as @a … as @e[distance=129..] run 杀` 是"逐个玩家各杀一遍"，与"对所有玩家都超距"**不等价** ——
前者是「∃ 玩家超距 ⇒ 杀」，后者是「∀ 玩家超距 ⇒ 杀」。差一个量词。

### 2.2 修复后的写法（v4.22，标记-清扫两遍）

```mcfunction
# ① 清标记 ② 任一玩家 128 格内（WATER_AMBIENT 64 格内）打 near 标记 ③ 没有 near 标记的才消失
tag @e[tag=doom.nats.spawned,tag=doom.nats.near64] remove doom.nats.near64
tag @e[tag=doom.nats.spawned,tag=doom.nats.near128] remove doom.nats.near128
execute as @a[gamemode=!spectator] at @s as @e[tag=doom.nats.spawned,distance=..64] run tag @s add doom.nats.near64
execute as @a[gamemode=!spectator] at @s as @e[tag=doom.nats.spawned,distance=..128] run tag @s add doom.nats.near128
execute as @e[tag=doom.nats.spawned,tag=!doom.nats.near64,tag=!doom.nats.persistent,nbt=!{PersistenceRequired:true},type=#doom.nats:water_ambient] unless data entity @s Passengers run function doom.nats:util/void_kill
execute as @e[tag=doom.nats.spawned,tag=!doom.nats.near128,tag=!doom.nats.persistent,nbt=!{PersistenceRequired:true},type=!#doom.nats:water_ambient] unless data entity @s Passengers run function doom.nats:util/void_kill
```

概率消失（`$despawn_dice`，默认关闭）同族修法：先打 `near32` 标记，只对没有标记的掷骰。
生成器：`tools/gen_ctm_despawn.mjs`（改生成器 → 重新生成 → `--check`，未手改产物）。

## 3. 差在哪

| 场景 | 原版 | 修复前 | 修复后（v4.22） |
|---|---|---|---|
| 单玩家 | 出 128 格消失 | 出 128 格消失 ✔ | 同 ✔ |
| 两玩家相距 460 格 | 各自身边的怪**都留着** | **都被对方判掉**（场上瞬间清空） | 各自身边的怪都留着 ✔ |
| WATER_AMBIENT | 出 64 格消失 | 出 64 格消失 ✔ | 出 64 格消失 ✔ |
| 无玩家在线 | 不动 | 不动 ✔ | 不动 ✔（标记全是 0 ⇒ 全部超距？—— 见下） |

> 无玩家在线时的细节：修复后"没有任何 near 标记"= 全部都在 64/128 格外 ⇒ 会被判消失。
> 原版此时 `getNearestPlayer` 返回 null ⇒ **不判定**。因此修复里保留了 v4.17 的约定：
> 标记命令是 `as @a[…]`，无玩家时**一条都不会执行**，但①的清除与③的扫描仍会跑 ⇒ 需要一个"有玩家才跑"的守卫。
> **v4.22b 已补**：③ 两条前面各加 `execute if entity @a[gamemode=!spectator]`。
> 实测：停机前最后一批怪不再被"无人在线"的那一拍清掉。
