## 3. 修掉的两个真 bug

### 3.1 单类别群系不显式置 `$catid` ⇒ 整片群系随机不刷怪（**原版就有 7 个群系中招**）

- **现象**：P2b 第一次跑（修前）——roster 明明只剩 husk，真机却 **生成 +0、`reason=8` +1891**（= 选不到物种）。
- **根因**：`mob/biome/<群系>.mcfunction`（类别分发）里，多类别群系用
  `execute store result score $catid … run random value 0..N-1` 覆盖 `$catid`；**单类别**群系生成器只写了一句注释，
  没有赋值，于是 `$catid` 沿用**上一个群系**留下的 0..N-1，随后那句 `if score $catid matches 0 run function …/monster` 就随机不成立
  ⇒ 该群系整片不刷怪。`$catid` 是全局计分板，跨维度、跨群系都带过去。
- **受害面（原版构建里就存在）**：`the_end` / `end_barrens` / `end_highlands` / `end_midlands` / `small_end_islands` / `deep_dark` / `the_void` ——
  7 个单类别群系，全是「只有 monster」。也就是**末地刷怪与深暗之域刷怪会随上一个群系的抽取随机失效** ✓
  （地图把某群系覆盖成「只有一类」时同样中招，这正是 Q7 场景）。
- **修复**：`doom.nats/tools/gen_ctm_mobs.mjs`（单类别分支显式 `scoreboard players set $catid doom.nats 0`）+ 新增 lint **L14**
  （群系类别分发若含分发行却不设 `$catid` ⇒ ERROR；反向测试：故意去掉即报 `❌ L14 …`）。
- **修复后真机复测**：P2b **+59 只 husk、活体 70、`reason=8` 归 0**，其它物种全 0 ✓（同一世界、同一实例、同一脚本）。

### 3.2 生成器只写不删 ⇒ 陈旧 roster 文件变成「幽灵物种」

- **现象**：Q7 覆盖测试后，包里仍留着上一次构建的 `mob/biome/plains/creature.mcfunction`、`ambient…`、`underground_water_creature…`
  （覆盖成「只有 monster」后这三份旧表本不该在）；更早的实验甚至把 `mob/biome/wgtest/**` 两个文件**装进了用户存档**，
  而 `--check` 看不出来（它只比对新写内容，不比对目录里多出来的文件）。
- **修复**：`gen_ctm_mobs.mjs` 写出后清理 `mob/biome/**` 中不在本次产出集合里的文件（并收掉空目录）；
  `--check` 模式把「陈旧文件」也计入漂移 ⇒ 静态门能挡住复发。清理范围只限本生成器独占的目录 ✓。
- **效果**：原版构建从 586 → **584** 文件（清掉 2 个 `mob/biome/wgtest/**` 幽灵文件）；9 个生成器 `--check` 全部「一致」✓。

### 6.1 本轮为了拿到干净数字，顺手修掉的「测试前置」问题（都是假红）

1. **`verify_animals` 在门里红 / 单跑绿（4 PASS / 2 FAIL）** —— 根因是**容量冻结**：
   `$cap.<cat> = maxInstancesPerChunk × spawnableChunkCount / 289`，`spawnableChunkCount` 来自**快照**；
   上一个脚本 `verify_aabb_cheap` 会 `$snap_period=20000 / $eff.period=100000` 冻结节拍且**不解冻**，
   若冻结发生在玩家刚进场、快照还没把区块算进来时 ⇒ `$cap.creature` **永久为 0** ⇒ 40 次尝试全 `reason=5`（`0>=0`）。
   修：脚本自己在判定前 `function doom.nats:circ/snapshot` 强制跑一拍 + 轮询 `$cap.creature>0`；并把「清场 ⇒ 等额度释放」写成显式前置。
2. **反向教训**：我一度在门的 ③ 里给每个脚本统一「解冻」（`$snap_period=0`），结果 `verify_persist` 9/1、`verify_rules` 9/7、
   `verify_struct_aabb` 6/3 集体转红（明细日志里 `$eff.period=2` 说明刷怪循环恢复、把它们的 `$sel.*` 冲掉了）。
   **多数 verify_* 是「先冻结再戳分数」的写法，冻结就是前提，不能替它解冻** —— 已撤回并在 `gate_merge.mjs` 里写明。
3. **`verify_dims` 12/1 抖动**：③ 的前提是「玩家露天」，抬到 y=120 时若那一列区块还没加载，高度图读不到 ⇒ 假红。
   修：抬人前 `forceload add` 目标区块 + 轮询重试，判完 `forceload remove`。
4. **`verify_probe_cost` 2/1 抖动**：② 原用「第 2..5 次**平均** < 5ms」，被第 2 次那一发预热抖动（实测 16ms）拉爆（5.8ms）。
   修：改**中位数**口径（并打印样本与均值）。
5. **`_work/gate_merge.mjs`**：现在把每个脚本的**完整输出**落盘到 `_work/gate-<时间戳>-detail/<脚本>.log`
