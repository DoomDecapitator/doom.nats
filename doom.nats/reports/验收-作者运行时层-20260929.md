# 验收报告 · 运行时刻作者层 v4.24（2026-09-29）

> 目标（SPEC-运行时作者层.md）：把「可自定义」从**构建期**（`rules/*.json` + 重生成）推到**运行时**——
> **玩家在游戏里改 storage 即刻生效，不用重生成包、不用重装、不用重启。**
>
> 三层身份：① **原版复刻**（默认；`rules/` 空 **且** 运行时刻 storage 空 ⇒ 逐条与原版一致）
> ② **本包扩展（稳定）**：逐实体补丁 / 条件条目 / 数量随 Y（运行时刻可改）
> ③ **实验性（非原版）**：`near` 关系条件 / `on_spawn` 演出钩子 / `preset` 预设 —— 只在**实验性变体** `v4x` 里，
> 产物一律落在 `doom.nats:exp/*`（函数）、`doom.nats.exp.*`（实体标签）、`doom.nats:exp`（storage）。
>
> 全程只碰隔离实例 **fid（25571 / RCON 25581）**；没碰用户主服 25565；只改生成器再重生成，没手改产物；没有 git push。

| 用例 | 探针（确定性，固定 `$rng`/`$py`） | 原版会怎样 | 本包默认变体 | 差在哪 |

## 三、引擎门（实验性变体）真机取证

| 场景 | 观察 | 证据 |
|---|---|---|
| 世界**没开**实验性玩法（全新世界） | 包在 enabled 列表里，但**数据不加载**：`function doom.nats:exp/usage` = `Unknown function doom.nats:exp/usage`；启动日志无 features 报错 | fid 全新世界 + v4x，启动态探针 |
| 同世界 `/datapack enable "file/doom.nats"` | **被引擎拒绝** | `Pack 'file/doom.nats' cannot be enabled, since required flags are not enabled in this world: minecraft:minecart_improvements!` |
| 世界**开了**实验性玩法（`initial-enabled-packs=vanilla,minecart_improvements`） | 加载成功：`author/load` 与 `exp/usage` 都可调用；`datapack list` 里出现 `minecart_improvements (feature)` | 同一实例、全新世界、启动态探针 |
| 默认变体（无 `features`） | 同一世界正常加载、`/reload` 0 错误 | `verify_author_rules --expect default` 5/0 |
| ⚠ **坑（必须写清）** | **`/reload` 会绕过这道门**：reload 之后实验性变体即使在没开旗标的世界里也会被加载（真机复现）。另外若该包已在世界 enabled 列表里，服务端会 `Found feature pack ('minecart_improvements') for requested feature, forcing to enabled` **强行把原生实验性包打开** | 启动日志原文 |

⇒ 结论：**引擎门在"启用/选择"这一步是硬拒绝**（客户端 UI + `/datapack enable` 都不给过），
但服务端的"文件夹自动发现 + `/reload`"两条路径会绕过它。发货建议：以**世界装载态**为准，
或用 UI 确认包列表；双轨开关的另一半（`doom.nats:exp enabled`）负责"行为回滚"，不负责"能不能装"。

## 四、机制（改了什么，凭什么等价/不回归）

| 件 | 生成物 | 说明 |
|---|---|---|
| 运行时刻 storage | `doom.nats:author`（= `rules/*.json` 同构）/ `doom.nats:exp` | 判定**当场读**；`load` 只是刷新摘要缓存，不 load 也生效 |
| 通用派发 | `author/row`（选物种时装载补丁 + Y 段）· `author/{below,biome,rule,cap}_*`（判定时逐条读）· `author/entry_*`（条目加权派发）· `author/emit_rt`+`post_rt`（生成 + `$data merge entity @s $(nbt)`） | 上限：条目 8 · Y 段 8 · 落位面标签 8 · 群系名单各 4（运行期固定槽位） |
| 挂点 | `mob/biome/<群系>/<类别>`（表头条目扫描 + 命中行的 `author/row`）· `check/block`（belowAny）· `check/entity`（Y/亮度/天气/群系）· `check/cap`（容量随 Y）· `spawn/emit`（三路派发：运行时刻条目 / 实验性条目 / 香草）· `spawn/group`（每组清标记） | 空层时全部被守卫挡住 ⇒ 逐条与原版一致 |
| 命令面 | `author/{help,show,load,reset,export,demo,add_entry,add_below_tag,set_group_by_y,set_cap_y}` + `exp/{…,enable,disable,preset}` | `/function` 没有内联参数 ⇒ 统一走 `<ns>_in` 入参 storage（文档里给了完整命令） |
| 变体 | `v4/doom.nats`（默认）· `v4x/doom.nats`（实验性，`DOOM_EXP=1`） | 产物根目录由 `tools/lib/packdir.mjs` 统一解析；`check_static` 两变体都跑生成器 `--check` 与 lint |

**空层零行为差异怎么保证的**：所有运行时刻通路都是"一次 `if data storage …` 守卫 + 一次调用"，
storage 空时守卫恒假；`$auth.loaded/$exp.loaded/$exp.on` 这些标记也只在真装载后置位。
因此 `verify_author_runtime` 的 §1 专门断言"空层 = 原版"（组大小 4/4/4 · 树叶 `ok=0 reason=4` · `rng=600` 不命中作者条目），
且 `verify_author_rules` 的 default A/B 仍然是 5/0。

## 五、本轮挖出来的既有问题（都已修/已加固，值得单独记账）

1. **`doom.nats:water_fluid` 是手写进产物的孤儿文件**：没有任何生成器产出它 ⇒ 新变体 `v4x` 里缺它，
   `check/entity` **整函数加载失败**（真机：`Unknown block tag 'doom.nats:water_fluid'`）。
   已收进 `gen_ctm_check.mjs`（两变体都有）。**教训**：产物里"生成器不管的文件"是变体构建的隐形地雷。
2. **`data merge` 是递归合并 ⇒ `sel.nbt` 会把上一条目的键粘到下一只身上**（真机实测：作者条目的
   `CustomName`/`HandItems` 残留到下一只香草生物）。已改成"结构字段 `merge` + `nbt` 整体 `set`"（`mob/biome`、要塞表、
   结构覆盖表、构建期作者条目、运行时刻 `entry_take` 全部改齐）。回归用例：`verify_author_runtime` §9b。
3. **1.21.5+ 的装备 NBT 是 `equipment:{mainhand:…,head:…}`**；老的 `HandItems`/`ArmorItems` 被**静默忽略**。
   `rules/examples/full/entries.json` 与 README 示例已改，并写进坑清单。
4. **测试台自身的两条坑**（v4.22d 纪律的补课）：`verify_author_rules.mjs` 建台子前只 `forceload` + 800ms，
   不校验加载态 ⇒ 台子建在未加载区块里时 `if block` 恒假，**默认变体假绿、author 变体假红**
   （本轮 auto_gate 第一轮就是这样红的）。已加"强加载 + `if loaded` 轮询 + `if block` 回读，失败即 exit 3"。
5. 引擎/命令语义（都真机验证过）：宏**缺参**会让**被调函数整体中止**（消息 `Failed to instantiate … Missing argument`），
   但嵌套调用里的失败**不会**连坐调用者；`data remove storage <id>` 必须带 path；
   `execute if data storage <id>{…}` 是**非法语法**（`trailing data`）；`if biome` 与谓词 id 都能吃宏替换的字符串。

## 六、诚实清单（没做 / 做不到 / 取舍）

| 项 | 状态 | 说明与替代方案 |
|---|---|---|
| 运行时刻改 `coins/cluster/deep/sky/…` 等**源码级开关** | ❌ 未做 | 这些决定 `check/entity` 的**函数体形状**（生成期展开），运行时刻只能改"数据"改不了"形状"。替代：`rules/entity-rules.json`（构建期）+ `place`/`light`/`yMin,yMax`/`lightMin,lightMax`/`weather`/`biomeIn,biomeNot` 的运行时刻覆盖已覆盖绝大多数需求 |
| 运行时刻**新增群系**（给原本没有任何 monster 的群系加怪物） | ❌ 做不到 | 需要 `mob/biome/<群系>/<类别>` 这个函数存在 ⇒ 得改 roster / worldgen 覆盖（`tools/apply_worldgen.mjs`）。运行时刻条目只能加到"该群系已有该类别"的表里（与构建期同源限制） |
| 运行时刻条目**不走 SpawnGroupData**（组/变体层） | ⚠ 有取舍 | `author/emit_rt` 只用 `post_rt`（标签 + 作者 NBT + 持久化 + 朝向）；`grp/init|mem` 只在查到 slug 时走 `entry_rule`，实际上运行时刻条目**不做**变体/婴儿的整组共享。要完整组语义请在 `rules/entries.json` 里加（构建期条目走 `post/<slug>` 全链路） |
| 运行时刻数组**超过槽位上限** | ⚠ 硬上限 | 条目 8 / Y 段 8 / 落位面标签 8 / 群系名单各 4（SPEC 指定）。超出的写入会被命令面拒绝并提示（`tellraw`），手写 storage 超出部分**不生效**（不报错） |
| `on_spawn` 只对**实验性层**条目生效 | ⚠ 取舍 | 它属"非原版能力"（SPEC 追加第 4 条），所以构建期 `rules/entries.json` 的条目与稳定层条目都不会触发钩子。想要演出就把它写成实验性条目 |
| 引擎门借用原生旗标 | ⚠ 不可避免 | 1.21.6 没有"自定义数据包"旗标（jar 里只有 `minecart_improvements`/`redstone_experiments`/`trade_rebalance`）⇒ 开它的世界**同时**拿到 vanilla 的矿车改动。且 `/reload` 会绕过门（见 §三） |
| 运行时刻的**行尾/槽位可视化**（在游戏里看"现在覆盖了什么"） | ⚠ 部分 | `author/show` 打印摘要 + `data get storage` 全量；没有 GUI。`author/export` 可复制成一条 `data modify` 命令 |
| `near` 的计数是"每次尝试 1 次查询" | ⚠ 性能取舍 | 只查一次（SPEC 的上限要求），计的是 `@e[type=…,distance=..r]` 的**当前数量**，不区分"是不是同一群" |
| 实验性变体的真机验收是在"旧世界（旗标未开但包已 enabled）"上跑全套 | ⚠ 环境限制 | 全新世界 + 旗标那轮的 §0/§8 两条受环境拖累（夹具包 `nats.debug:p0` 加载失败 1 个、无玩家在线导致本地容量 `reason=6`），已定位为环境因素；权威数字用旧世界的 19/0 |
