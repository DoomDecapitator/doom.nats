# 极端 E2 · 限制性维度（2026-09-29 · E1 实例）

## E2a 光照门两端（同一条水柱，水顶 62）

| 时刻 | y=50 | y=54 | y=57 | y=60 | y=62 |
|---|---|---|---|---|---|
| midnight | 过 ✓ | 过 ✓ | 过 ✓ | 过 ✓ | 过 ✓ |
| noon | 过 ✓ | 过 ✓ | **拒 r3** | **拒 r3** | **拒 r3** |

**原版**：`isDarkEnoughToSpawn` = 天空光 ≤ `rand(32)` ∧ 综合亮度 ≤ `uniform(0..7)`（**随机阈值**）。分界线位置与实测一致（54 过 / 57 拒）。
**本包**：`check/light` 的 dark 档 = 固定阈值（`predicate light/tier_7` ⇒ 亮度 ≤7）⇒ 分界线是**硬的**。
**差在哪（保真度差异 #1）**：原版在临界亮度层是**概率性通过**（亮度 L 时约 `(8-L)/8`），本包**全过或全拒** ⇒ 正午水面下 5~8 格这一带本包偏**严**，会把原版里稀疏能过的那种压成 0。数据包无法表达 `rand(32)` ⇒ 若要更贴近，只能在那条门前再加一层按亮度档换算的 `coin`。

### 门③ 假红清单 · 追加（v4.20 第 57–60 轮）

| 脚本 | 红 | 根因 | 处置 |
|---|---|---|---|
| verify_nether ② 下界窗口报 50..63 | 旧假设 + **读数竞态** | ① 脚本只设 `$snap.dim`，而 `check/sealevel` 现读 `$att.dim`；② `$chk.sea_lo/$chk.sea_hi` 是全局计分板，活循环每 tick 会改写 ⇒ 两次 RCON 读之间被覆盖（实测 lo=19 对、hi 被改成 63） | 脚本先写 `$att.dim`、并在**短暂冻结**下一次读完 ⇒ **4 PASS / 0 FAIL** |

**两条可复用的诊断经验**：
1. **全局计分板 + 活跃循环 ⇒ 任何「分两次读」的断言都可能在两次之间被改写**；正确姿势是「短暂冻结 → 一次读完 → 立刻解冻」，而不是靠读得够快。
2. **改了「谁写哪个计分板」之后，必须搜一遍所有 verify/门脚本里对该计分板的依赖**（本轮 `$snap.dim → $att.dim` 一次性牵出 `verify_dims` / `verify_nether` 两处假红）。

## E2c worldborder 缺口（实测确认，带数字）

布场：E1 世界 `worldborder center 0 0` + `worldborder set 64`（合法范围 **-32..32**），用**无硬币**物种「鱿鱼 rule 9 / place 3」做判据（避免被 1/40 硬币噪声污染）。

| 候选点 | 该格是水 | 结果 | 原版 |
|---|---|---|---|
| (0,55,0) 边界**内** | 是 | **过** ✓ | 过 |
| **(100,55,0) 边界外**（仍在玩家 128 格内） | 是 | **过 ⚠ 缺口** | **拒**（`IN_WATER`：`level.getWorldBorder().isWithinBounds(pos)` = false） |
| (200,55,0) 边界外且 >128 格 | 否 | 拒 r2（**距离门**，不是边界门） | 拒 |

**结论**：本包**没有任何 worldborder 判定**。原版 `SpawnPlacementTypes` 的三种落位（`ON_GROUND` / `IN_WATER` / `IN_LAVA`）**都**先查 `level.getWorldBorder().isWithinBounds(pos)`。
**影响面**：只有当"缩小过的边界 + 玩家距边界 < despawnDistance(128)"时才暴露 —— 但 CTM/冒险地图（本包的典型用户）**恰恰常缩边界**，所以这是真实缺口，不是理论问题。

**修法（下一轮实施并验证）**：
1. 配置层加 `border: { centerX: 0, centerZ: 0, size: 0 }`（`size=0` = 关闭 ⇒ 默认行为不变；命令侧只能读 `worldborder get` 的**尺寸**、读不到**中心** ⇒ 中心必须由作者声明，与 `spawnX/Y/Z` 同一套路）；
2. 新增生成函数 `check/border`：`size>0` 时用候选点绝对坐标（`$wx`/`$wz`，由 `pos/hit`/`spawn/walk` 维护）判 `|x-cx|*2 > size` 或 `|z-cz|*2 > size` ⇒ `fail {reason:11}`；
3. 挂进 `check/all`（与 `check/distance` 同级，位置越早越省），并把 reason 11 加进 `debug/reject_report` 的清单。

### E2c 修复验收（真机，命令侧边界 size=64 ⇒ 合法 x ∈ [-32,32)，原版半开区间）

| 阶段 | `$cfg.border_size`（读回生效值） | x=0 | x=31 | x=32 | x=100 |
|---|---|---|---|---|---|
| **A 默认（未声明）** | **0** ✓ | PASS | — | — | PASS（老行为不变 ✓ 无回归） |
| **B 声明 `center 0,0 size 64`** | **64** ✓ | PASS | PASS | **REJ r11** | **REJ r11**（缺口已闭合 ✓） |
| **C 撤销配置** | **0** ✓ | — | — | — | PASS（干净回退 ✓） |

**判读**：右端点 32 **拒**、31 **过** ⇒ 与原版 `WorldBorder.isWithinBounds`（`x >= minX && x < maxX`）的**半开区间**一致；声明后 100 格处从"过"变 `r11` ⇒ E2c 缺口闭合；未声明时行为与修前完全一致 ⇒ **opt-in，不影响老地图**。三阶段都做了"配置生效值回读"（0/64/0 ✓），符合本目标的容量/密度类纪律。
