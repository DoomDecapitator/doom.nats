# 诊断：水里看不到溺尸（2026-09-29 · v4.19）

> 现场：Doom_Flare 在水里看不到溺尸。查下来 **四个原因、其中三个是真 bug**，
> 其中一个是**全局权重失效**（P0）——不止溺尸，所有生物的权重刷怪都不生效。

---

## 二、四个修复的落点（都改生成器，不手改产物）

| 修复 | 生成器 | 产物 |
|---|---|---|
| P0-4 `$rng` 自掷 | `tools/gen_ctm_mobs.mjs`（群系分发表头部） | `mob/biome/<群系>.mcfunction`：新增 `execute store result score $rng doom.nats run random value 0..999999` |
| P0-5 取点回退 | `tools/gen_ctm_pos.mjs` | `pos/band.mcfunction` 回退段 + 新函数 `pos/band_fallback.mcfunction`（`random($(yLo)..$(yHi))`，yHi=玩家层+2、yLo=维度下界） |
| P1-10 极性 | `tools/gen_ctm_check.mjs` | `check/entity.mcfunction`：`if predicate biome_river` 才掷 1/50 |
| P1-11 脚下水 | `tools/gen_ctm_check.mjs` | `check/entity.mcfunction`：溺尸两条分支**共用**的新否决行 |

配置层新增（`tools/gen_ctm.mjs` → `cfg/setup`+`cfg/apply`+`check/sealevel`）：

```jsonc
{
  "floorY": { "overworld": -64, "the_nether": 0, "the_end": 0 },   // 新增：取点回退的均匀分布下界
  "band": { "mode": 0, "yMin": 60, "yMax": 70, "jitter": 3, "fallback": 1 }  // fallback=1 启用回退
}
```

回退语义 ≈ 原版的 `getRandomPosWithin`（y 在 `[minY, 地表+1]` 整列均匀）：玩家在水面时
`[floorY, 玩家层+2]` 与 `[minY, 地表+1]` 几乎重合；**只在「模式 0 ∧ 扫不到地面 ∧ fallback=1」时触发**，
陆地上扫得到地面 ⇒ 行为完全不变。回退点会有一部分落在石头里被 `check/block` 拒掉——与原版"抽了才知道"同构。

### 3.1 物种权重真的生效了

冻结 `$snap_period=20000` + `$eff.period=20000`（**正确冻结法**：只冻 `$eff.period` 会被 `circ/snapshot → circ/apply` 一秒内还原），
**不预掷 `$rng`**，直接调生产分发表：

- `mob/biome/ocean` × 200：选中 **11 种**物种；蜘蛛（表首行）**2%**（修复前 100%）；monster 类别份额 **18%**（5 类均匀 ⇒ 20%）
- 桶对齐（确定性）：ocean/monster **9/9** 行、要塞 **5/5** 行，摆 `$rng` = 该行桶起点即命中该行物种（含溺尸 515..519）

## 四、诚实说明：**就算修好，海洋里溺尸本来也极少**

按原版权重与门的复算（每次"候选点"）：

```
P(溺尸) = P(候选点是水 0.32) × P(类别=monster 1/5) × P(表内权重 5/520)
        × P(1/40 掷币) × P(y < 58) × P(够暗)
        ≈ 1e-5
```

而本包每 tick 的尝试量远低于原版（`spawn/batch` 注释已声明是设计取舍：默认 `batch=6 / period=4` ≈ 1.5 次/tick，
原版是"每个合格区块每 tick × 12 个点位"）。`density=0` 时 AIMD 密度控制器不介入。

**所以：**

1. **河流才是溺尸的主场**：river 表权重 100/615（16%）、掷币 1/15、且**没有深度门**（`#more_frequent_drowned_spawns` = 河流标签）；
   海洋只有 5/520 + 1/40 + y<58 三连。
2. 想"看得见"：去**河**里（夜里更亮眼），或**深海 y<58** 的水柱里蹲一会。
3. 想更快：`data merge storage doom.nats:config {batch:24}` 或设 `density:300`（让 AIMD 自动加批）。

## 五、口径修正（这次踩到的三个"探针陷阱"，已写进 AGENTS）

1. **冻结必须冻 `$snap_period`**：只设 `$eff.period=20000` 没用——`circ/snapshot` 每 20 tick 跑一次 `circ/apply`，
   一秒内就把 `$eff.period` 还原（`$eff.batch` 不还原，因为它只由 `ctrl/aimd` 改）。实测被坑了一轮，读数全是 clobber 后的噪声。
2. **探针不要自己掷 `$rng`**：老 `verify_*`/`_probe_*` 自己补掷 `$rng`（还常写 `0..99`/固定桶）
   ⇒ 恰好掩盖了 P0-4：测试全绿、生产全退化。新门 `verify_species_mix.mjs` 明确**不预掷**。
3. **长命机器人要活在 DSH 进程树之外**：`run_code`/bash 程序结束时进程树会被回收（实测机器人 12–13 秒即掉线，
   日志里只有 `lost connection: Disconnected`）。改用 `powershell Invoke-CimMethod Win32_Process Create` 起（`_work/start_bot.ps1`）。
